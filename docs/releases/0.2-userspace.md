# Release `0.2-userspace` — RASCUNHO (publicar após `0.1-kernel`)

**Marco:** Plano Mestre §7 — processos de usuário isolados, IPC por handles/canais, init +
service manager, ABI v0 documentada.
**Estado:** todos os itens pendentes do marco foram concluídos em 2026-08-30; a publicação
respeita a ordem dos marcos (§RELEASE.md: uma versão só sai com o gate da anterior atendido).

## Critérios do gate F2 — atendidos (testes no boot a cada push)

- 4+ processos isolados simultâneos; serviço (`echo`) reiniciado 2× pelo `svcmgr` sem
  reiniciar o kernel (`user_services`).
- Negação por direitos (`Denied`), handles inválidos (`BadHandle`), isolamento de memória e
  de instruções privilegiadas (`user_isolation`, `user_syscall_error`).
- Fuzz de syscalls (20 000 por rodada) sem pânico nem vazamento (`user_syscall_fuzz`).

## Itens do marco concluídos hoje

- **IDL e protocolos tipados**: `idl/*.idl` → `tools/idlgen` → `abi/proto` (cabeçalho NXIP,
  `docs/spec/ipc-compat.md` §2); todos os protocolos de serviço migrados (rng, block,
  console, input, fs, esp).
- **Shell de diagnóstico** na console VirtIO (cenário `shell`, interativo de verdade).
- **Fuzzing contínuo**: `make fuzz` com sementes aleatórias registradas + workflow semanal
  (`.github/workflows/fuzz.yml`; execução manual: PASS).

## Para publicar (após a tag `v0.1-kernel`)

```sh
make ci                       # clone limpo
git tag -s v0.2-userspace     # a partir de 0.2 as tags sao assinadas (RELEASE.md)
git push --tags               # anexar nexo.img, kernel.elf, kernel.sym, BOOTX64.EFI, SHA256SUMS
```

## Limitações conhecidas

Uma thread por processo; sem memória compartilhada nem espera múltipla (blocos futuros);
canais do bring-up (`svcmgr`/`echo`) ainda com mensagens cruas; DMA sem IOMMU (ADR-0015).
