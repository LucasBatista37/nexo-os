## Demonstração obrigatória

```sh
git clone <repo> nexo-os && cd nexo-os
rustup show && tools/check-toolchain
make image            # build/nexo.img (GPT + ESP FAT32: BOOTX64.EFI, nexo/kernel.elf, nexo/boot.cfg)
tools/test-qemu       # 4 cenários headless; boot: 15/15 testes, código de saída 33
make run              # com display: barra do loader no framebuffer + console do kernel
```

## Verificação em ambiente limpo (Gate F0)

Executada em 2026-08-29 em um clone novo do repositório (diretório temporário) com `make ci`: lint, 44 testes de host, imagem, 4 cenários de QEMU e comparação de reprodutibilidade — resultado registrado no final deste arquivo.

## Compatibilidade

Primeira versão: nenhuma mudança incompatível a relatar. ABI de boot v1 (`docs/spec/boot-abi.md`).

## Limitações conhecidas e regressões registradas

- Somente QEMU q35/UEFI com `-cpu qemu64`; hardware real não suportado.
- PIC/PIT legados; sem APIC, SMP, preempção, modo usuário, armazenamento ou rede.
- Console de framebuffer sem rolagem (volta ao topo).
- Os 3 quadros de tabela usados pelo mapeamento identidade do loader não são liberados pelo kernel (12 KiB).
- `LoaderReclaimable` é liberado integralmente; runtime services UEFI não são chamados nesta versão (se forem, precisarão de mapeamento próprio).
- Nenhuma regressão conhecida.
